# Observe

Ditulis lewat `/bfb-observe` (dan `/bfb-review`) pada 2026-10-05. Alur: Rawat facebook (`postFeed`, menu 1), posting `PERSONAL` + `POST` teks saja. Akun yang diobservasi: 180 baris `workspaces/datas/contents.csv` (NO 1–198), campuran UI Inggris dan Indonesia, akun biasa dan mode profesional ("Digital creator"/"Kreator digital"). Lingkungan: Chrome 147 headful, `xvfb-run -s "-screen 0 1920x1080x24"`, viewport efektif 1238×768; sebagian run di desktop GNOME user. Bukti di `temp/observe/` dan `temp/fb-debug/` (di-gitignore): `NO-<n>.png/.html/.url`, `consent-*.png/.html`, `run.log`.

## Tanda berhasil dan gagal

- Berhasil: composer tertutup (P7). Facebook kadang menerbitkan postingan tapi menutup composer terlambat; sebelum menyatakan gagal, caption dicari di halaman di luar dialog (`feedCaptionSelector`). Batasnya: caption yang sama dari posting lama juga cocok.
- Persetujuan berhasil: profil yang dibuka ulang tidak lagi diarahkan ke `/privacy/consent/`. Tanpa klik "Tutup" (C3), persetujuan tidak tersimpan (NO 106: setelah "Saya setuju" tanpa "Tutup", profil dibuka ulang masih ke halaman persetujuan).
- Gagal sebelum publish (caption kosong, `Publish tidak valid`, halaman tidak terbuka) aman diulang; gagal setelah klik publish harus dibuktikan dulu tidak terbit.

## Lingkungan dan timing

- Viewport efektif 1238×768 dengan `--window-size=1280,900`. Elemen di bawah y=768 harus digulir dulu (`humanClick` memanggil `scrollIntoView`).
- Jendela yang tidak tampil (xvfb, workspace lain) membuat Chrome hanya 2–5 frame/dtk, atau `requestAnimationFrame` macet. Composer tidak menutup dan locator/`waitForSelector` macet sampai timeout, padahal postingan terbit. `--disable-frame-rate-limit` memulihkan ke 60–61 frame/dtk (diukur di xvfb; belum di desktop GNOME).
- Facebook tidak pernah "network idle" karena koneksi long-polling; `waitForNetworkIdle` membuat alur persetujuan 46 dtk, sedangkan menunggu tanda di halaman membuatnya 21 dtk.
- Waktu per baris: 35–50 dtk ditambah jeda antarbaris 5–15 dtk.

## Belum terobservasi

- Langkah mematikan "Boost post" (P5) belum pernah terpakai di akun sungguhan sejak fix; selector hanya terbukti terhadap `NO-3.html`.
- Alur persetujuan privasi dalam UI Inggris (label "I agree"/"Close" diasumsikan dari pola label lain).
- `--disable-frame-rate-limit` di desktop GNOME dengan jendela di workspace lain, dan beban CPU-nya.
- Halaman checkpoint (`/checkpoint/`) dan verifikasi identitas: belum pernah muncul.

## Validasi

Run 180 konten (2026-10-04/05), status saat laporan ini ditulis: 161 terbit, 17 baris terakhir (NO 179–198) masih berjalan, 2 gagal karena sesi mati (NO 118 UID `61557170964063`, NO 171 UID `61556397145033`); keduanya perlu Sinkronisasi cookies sebelum diulang (`bfb -b 1 -e 118,171`). Penyebab kegagalan yang ditemukan dan diperbaiki, berurutan: composer di bawah layar (scroll), Boost post ON, render tersendat (frame rate), modal "Pembaruan reel" (dismiss + ketik ulang), awal caption hilang (klik textbox), panel "Pembaruan Reels" (Oke), halaman persetujuan privasi (otomatis atas keputusan user, termasuk "Tutup"), sesi mati di profil publik (form login). Rincian fix dan test di `architecture/BUILD.md`, `architecture/TEST.md`, dan bagian "Jebakan `postFeed`" di `AGENTS.md`.
